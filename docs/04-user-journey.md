## 여정에서 나온 발견 3개

### 발견 1 — 두 사람의 감정 최저점이 **같은 단계**에 있다
보호자 -1.5(6단계 "또 처음부터"), 시터 -2(6단계 "증명 못 함").
둘 다 **"다음 건"에서 바닥을 친다.** 돌봄 자체가 아니라 **건과 건 사이**가 문제라는 뜻이고,
이는 문제 정의(신뢰의 단위가 '건')를 여정 쪽에서 지지한다.

### 발견 2 — 시터의 통증이 더 깊은데, 완충 장치가 없다
보호자는 최소한 **감시**(라이브·사진)라도 갖고 있다. 불완전하지만 무언가는 한다.
시터에게는 대응 수단이 아예 없다 — 이력을 들고 나갈 방법 자체가 없기 때문.
→ 주 사용자를 시터로 잡은 결정을 지지.

### 발견 3 — CUJ의 병목이 **주 사용자가 아닌 쪽**에 있다
이력이 성립하려면 보호자의 확인(O4)이 반드시 찍혀야 한다.
그런데 보호자는 이 제품의 주 사용자가 아니다. **열쇠를 부 사용자가 쥐고 있다.**
→ 서비스 정책(`06`)에서 반드시 다뤄야 할 구조적 위험.

## Critical User Journey

> **CUJ 정의:** 보호자가 인계 카드를 만들고 → 시터가 수행을 기록하고 → 보호자가 확인을 찍어 →
> 그 이력이 **시터에게 귀속**되어 → **다음 고객에게 보여지기**까지.
>
> 이 한 바퀴가 끊기면 제품은 그냥 체크리스트 앱이 된다.

| # | 단계 | 화면 | 성공 기준 (측정 가능) | 끊기면 무슨 일이 |
|---|---|---|---|---|
| 1 | 인계 카드 작성 | O2 | 첫 작성 **10분 이내** / 필수 5항목 채움률 **100%** / 2회차 작성 **2분 이내** | 약속이 없으면 나머지 전부 무의미. 카톡으로 회귀 |
| 2 | 카드 열람 | S3 | 방문 **전** 열람률 **100%** / 방문 중 재열람 **1회 이상** | 안 읽으면 약속이 성립 안 함. 수행 기록이 형식이 됨 |
| 3 | 수행 체크 | S4 | 항목 체크 완료율 **≥90%** / **「못했음·이상」 사용 건이 전체의 ≥10%** | 「했음」만 100%면 정직 기록 실패 = 5whys V3 문제 그대로 |
| 4 | 완료·확인 요청 | S6 | 돌봄 종료 후 **10분 내** 발송률 **≥90%** | 지연되면 보호자 기억이 흐려져 확인 품질이 떨어짐 |
| 5 | **보호자 확인** | O4 | **24시간 내 확인율 ≥70%** | **최대 병목.** 확인이 없으면 이력이 성립하지 않음 |
| 6 | 이력 귀속 | S7 | 확인 건 누적 반영 **100%** / 시터의 7일 내 이력 열람 **≥1회** | 안 보면 IA 결정 1(이력 탭) 기각 |
| 7 | 이력 공유 | P1 | 시터 링크 공유 **월 ≥1회** / 링크 열람 **≥1건** | 아무도 공유 안 하면 "들고 다닌다" 가정 기각 |

### 가장 약한 고리: 5번
보호자에게는 확인을 찍을 **직접적 이득이 없다.** 시터의 이력이 쌓일 뿐이다.
정책 단계에서 이걸 풀지 못하면 CUJ는 5번에서 끊긴다.

### 3번이 이 제품의 진짜 시험대
「못했음·이상」 사용률이 0%로 수렴하면, 겉으로는 잘 돌아가는 앱이지만
**신뢰 장치로서는 완전히 실패한 것**이다. 이 지표를 대시보드 1순위로 둔다.
