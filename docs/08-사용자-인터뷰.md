---

## 문답

**Q1. 지난 돌봄에서 보호자에게 받은 정보 중, 현장에서 실제로 다시 꺼내 본 게 뭐였나?**
> "미리 보호자가 적어준 정보들을 **대화내용을 타고 올라가서** 다시 확인해보면서 이행하거나, 그때그때 당근톡 대화로 필요한 정보를 주고받았어"

**Q2. 못 지킨 일이 실제로 생기나? (약 안 먹음, 산책 거부 등)**
> "별로 없었던 것 같아"

**Q3. 그걸 보호자에게 그대로 말하나, 좋게 돌려 말하나?**
> "그대로 말하는 편이야 개인적으로. 근데 다른 말일수도 있는데, **'불안해 해요~'라기보다는 '잘 지낸다'고 안심시키는 편**이야. 아이가 조금 불안해해도."

**Q4. 다른 시터들은?**
> "이건 엄청 선량한 내 입장이고, 다른 펫시터들은 **거짓말을 할 수도 있을 것 같긴 해. 불이익이 걱정돼서.**" → **[당사자 추측]**

**Q5. 보호자가 가장 불안해하는 지점은?**
> "**혹시 말로만 잘 지낸다 하고 아니면 어쩌지?** 하는 부분"

**Q6. 시터로서 무엇을 보여주고 싶은가?**
> "이 강아지를 잘 돌볼 만큼 **나는 이렇게 강아지를 잘 돌보는 사람이다**를 보여주고 싶어"
> - 타 플랫폼에서 가져온 다른 보호자들의 후기
> - **내가 내 강아지를 얼마나 잘 돌보는지** 확인할 수 있는 페이지
> - 유기견 봉사나 기부 이력
> - 우리 강아지와의 일상 (구현 가능할지 모르겠다고 함)
> - 그때그때 사진·동영상으로 인증할 수 있는 장치

**Q7. 기록 요구는 어느 정도가 적당한가?**
> "시터에게 **너무 숙제처럼 느껴지진 않으면** 좋겠음. **우리 강아지가 지금 잘 살아서 안전하게 있구나를 보호자가 확인할 수 있는 정도만**"

---

## 발견

### 발견 1 — 근본 원인은 V2였다. V3 채택은 틀렸다
Q1의 답은 **V2**(정보는 받았으나 수행 시점에 못 찾음)의 정확한 서술이다.
`01-5whys.md`에서 V3를 판단으로 채택했으나, 실제 시터의 답은 V2다.

### 발견 2 — 왜곡의 대상이 「수행」이 아니라 「상태」다
Q2에서 미수행 사건은 드물다고 했다. 그런데 Q3에서 **아이의 상태는 완화해서 보고**한다고 했다.

> 기획이 겨냥한 것: "할 일을 했나" (수행)
> 실제로 왜곡되는 곳: "아이가 어땠나" (상태)

**과녁이 틀렸다.** F3(항목별 수행 3상태값)의 전제가 흔들린다.

### 발견 3 — 완화의 이유가 불이익이 아니다 ★ 가장 중요
V3의 Why 5는 "불이익이 걱정돼서 정직하게 못 적는다"였다.
그런데 대상자는 불이익 때문이 아니라 **안심시키는 것이 좋은 서비스라고 여겨서** 완화한다. 악의가 아니라 **역할 인식**.

**→ 정책 P2-1(못했음에 불이익 없음)만으로는 이 행동이 바뀌지 않는다.** 애초에 불이익 때문이 아니므로.
Q4의 "다른 시터는 불이익 때문에 거짓말할 수도"는 **당사자의 추측이지 관찰이 아니다.**

### 발견 4 — 신뢰의 근거가 「실적」이 아니라 「사람됨」이다
Q6이 이 프로젝트의 전제를 바꾼다.

| | 기획이 만들던 것 | 시터가 실제로 원하는 것 |
|---|---|---|
| 이력의 내용 | 확인된 돌봄 **건수** | **내가 어떤 사람인가** |
| 증거 | 보호자의 확인 | 타 플랫폼 후기 / 내 강아지 돌보는 모습 / 봉사·기부 |

문제 정의는 "신뢰의 단위가 **사람**"이라고 해놓고, 만든 것은 **건수 카운터**였다.

### 발견 5 — 요구 수준의 상한선이 생겼다
Q7이 기준을 준다: **상세 보고서가 아니라 생존·안전 신호.**
"숙제처럼 느껴지면 안 된다"와 "책임감이 없어지면 안 된다"(대상자의 별도 지적)는 모순이 아니라 **범위 지정**이다.

### 발견 6 — 당근 알바 채널
플랫폼이 없다. 정보는 **당근톡 대화에 묻힌다.** 일지·메모·이력 기능이 아예 존재하지 않는다.
→ 인계 카드가 대화 밖 독립 객체여야 한다는 `03-IA.md` 결정 2를 지지.

---

## 한계 — 이 인터뷰로 말할 수 없는 것

- **n = 1.** 일반화 불가
- **자기선택 편향.** 대상자가 스스로 "선량한 입장"이라고 밝힘
- **보호자 근거는 여전히 0명.** Q5의 보호자 심리는 시터가 추측한 것이지 보호자의 진술이 아님
- Q4(다른 시터의 거짓말)는 관찰이 아니라 추측

## 그럼에도 이 인터뷰가 강한 이유
발견 3은 **정직한 표본에서 나왔다.** "나는 그대로 말하는 편"이라고 한 사람조차 상태는 완화한다.
정직성이 높은 쪽에서 관찰된 행동이므로, 평균적인 시터에게는 더 강하게 나타날 가능성이 높다. **[추론]**

---

## 이 인터뷰가 만든 결정

1. `01-5whys.md` — V3 채택 철회. **V2 확인 + V3는 겨냥점 수정**(수행 → 상태)
2. `02-문제정의.md` — 신뢰의 근거를 「실적」에서 「사람됨」으로
3. `03-IA.md` — 이력 화면을 건수 카운터에서 **3층 프로필**로. 보호자를 1급 사용자로 복원
4. `07-PRD.md` — P0 재편. 상세 체크 → **가벼운 안전 신호**

- 다른 시터 2~3명. 발견 3(완화의 이유)이 재현되는지

# 사용자 인터뷰 #2 — 프로토타입 사용 (2026-08-04)

| | |
|---|---|
| 대상 | 동일 (당근 알바 펫시터 + 보호자) |
| 방식 | `prototype/index.html` v1(관찰값 3행)을 직접 사용 |
| 표본 | **n = 1** |

## 문답

**Q. 관찰 3행에서 실제로 뭘 고르게 되던가요?**
> "**전부 첫 번째(다 먹음 / 정상 / 평소처럼)를 고를 우려가 있겠어**"

## 발견 — 관찰값 3행은 기각됐다 ★

**「관찰을 묻는다」고 해놓고 실은 여전히 판단을 요구하고 있었다.**

> "다 먹음 / 절반 / 거의 안 먹음"
> → 시터는 **"이걸 절반이라고 해야 하나?"를 판단**해야 한다. 애매하면 좋은 쪽으로 반올림한다.

라벨만 관찰이고, 하는 일은 「양호 / 주의 관찰 / 이상 있음」과 같았다.

### 원인 셋 중 어느 것인지

| 가능성 | 판정 |
|---|---|
| ① 실제로 아이가 대체로 괜찮다 | 못 고침. 그러면 **지표(비-최상 ≥20%)가 애초에 틀린 것** |
| ② 여전히 안심시키고 싶다 (역할 인식) | 형식으로 안 바뀜 |
| ③ **선택지 간격이 넓어 좋은 쪽으로 반올림** | **설계 결함. 고칠 수 있음** |

### 이 인터뷰가 되살린 것 — Q6은 이미 답을 갖고 있었다

인터뷰 #1 Q6에서 대상자는 이미 말했다:
> "그때그때 **사진이나 동영상을 보내면서 인증**할 수 있는 장치"

기획이 이것을 P1으로 미뤘는데, **그게 본체였다.**

| | 값 고르기 | 사진 찍기 |
|---|---|---|
| 시터가 판단하나 | **함** (반올림 여지) | **안 함** |
| 상태를 판정하는 주체 | 시터 | **보호자** |
| 부담 | 3번 탭 + 판단 | 찍기만 |

**단, 사진에도 구멍이 있다** — 좋아 보이는 순간만 골라 찍으면 창고 사건(고양이 한 마리 사진만 옴)이 재현된다.
→ **찍을 대상을 지정**해야 한다.

## 한계
- **관찰이 아니라 예측이다.** "고를 우려가 있겠어"는 실제 선택 기록이 아니라 본인의 판단
- n=1, 동일 표본
- 사진 방식이 실제로 나은지는 **아직 검증 안 됨**

# 사용자 인터뷰 #3 — 지정 인증 사진 (2026-08-04)

| | |
|---|---|
| 대상 | 동일 | 방식 | `prototype` v2(밥그릇·배변 패드 고정 2컷) 직접 사용 | 표본 | **n = 1** |

## 문답

**Q. 사진 찍는 게 부담스러운가요?**
> "**사진 찍는 건 괜찮은데** 밥그릇은 좀 애매하네"

**Q. 그래서 어떻게 하면 좋겠어요?**
> "**보호자가 원하는 시간(밥, 산책 등)을 설정하고 그때그때 밥 인증 / 산책 인증 등 할 수 있게 연결**하는 건 어때?"

## 발견

### 발견 1 — 사진 부담은 통과했다 ✅
Q7의 "숙제처럼 느껴지지 않게" 기준을 사진 방식이 통과했다.
2차 수정의 가장 약한 고리로 표시했던 항목이 해소됐다.

### 발견 2 — 찍을 대상을 **기획이 고정한 것**이 문제였다 ★
밥그릇을 필수로 박아두면, 그날 밥을 안 주는 돌봄·자율급식 하는 집에서는 찍을 게 없거나 의미가 없다.
**대상을 지정한 건 맞았지만, 지정하는 주체가 틀렸다.**

| | 2차 수정 | 3차 수정 |
|---|---|---|
| 찍을 대상을 정하는 주체 | **기획(고정)** | **보호자(그 집에 맞게)** |
| 그날 없는 항목 | 못 보내거나 아무거나 찍음 | 애초에 요구하지 않음 |

### 발견 3 — 사용자 제안이 세 문제를 한 번에 푼다
1. 찍을 대상이 그 집에 맞게 정해진다
2. **시점이 붙는다** — `05-user-flow.md` 구멍 2(퇴근 후 몰아 찍기)가 자동으로 막힌다. 시각은 시터가 못 고친다
3. **버렸던 「시점 순 인계 카드」가 되살아난다** — 근본 원인 V2(정보를 수행 시점에 못 꺼냄)에 대한 답이 원래 이것이었다

## 한계
- 여전히 n=1, 동일 표본
- 일정 설정이 **보호자에게 새 일거리**가 된다. 부 사용자에게 게이트를 거는 패턴 — 과거에 한 번 틀렸던 것과 같은 모양
- 시각이 붙으면 **시간 압박**이 생겨 Q7 기준이 다시 위태로울 수 있음 → 지연에 벌점을 주지 않는 것으로 설계 (미검증)

# 사용자 인터뷰 #4 — 프로필 요구 + 실시간 확인 제안 (2026-08-04)

## 문답

**Q. 프로필에 뭘 넣고 싶은가?**
> "**당근 - 알바에서 받은 후기들 저장해서 자랑할 수 있게** (보호자 입장에서는 신뢰) 표시하고 싶어"

**Q. 인증 흐름에 더 필요한 게 있나?**
> "**일정을 인증했을 때 보호자의 상호작용 누르는 것도 필요할 것 같아. 이게 거짓말인지 진짠지 확인하는 장치로.**"

## 발견

### 발견 1 — 버렸던 「가져온 후기」가 실제 요구로 되살아났다
`09`에서 3층 프로필을 버렸는데, 그중 **층 2(가져온 후기)** 는 시터가 실제로 원하는 것이었다.
다만 검증이 안 되므로 **확인된 것과 자리를 나누는 것**이 조건이다.

### 발견 2 — 실시간 확인이 구멍 8을 메운다 ★
`09` 3차 수정의 기각 조건에 **"시터가 미리 몰아서 찍어두고 나중에 올리면 못 막는다"**를 적어뒀다.
업로드 시각만 기록되기 때문이다.

**보호자가 받는 즉시 확인을 누르면 그 시각이 남는다.**
→ 사후에 몰아 올리는 것이 어려워진다. 보호자가 그 자리에서 목격했다는 기록이 생기기 때문.
사용자가 이걸 "거짓말인지 진짠지 확인하는 장치"라고 표현했는데, 정확히 그 역할이다.

## 한계
- 보호자가 매번 누를지 미검증. 안 누르면 장치가 작동하지 않음
- 여전히 촬영 시각(EXIF)은 못 본다. 완전한 해결은 아니고 **비용을 올리는 것**

# 사용자 인터뷰 #5 — 추가 활동의 정체 (2026-08-11)

## 문답

**Q. 추가 활동에 뭐가 들어갈까? "점수와 별개"는 어때?**
> "추가 돌봄에는 **즐겁게 노는 모습, 잘 자고 있는 모습** 등이 들어갈 수 있을 것 같아.
> **보호자가 안심하도록 펫시터 입장에서 추가로 보여주는 화면**인데 **점수와 별개가 서운해.**"

## 발견

### 발견 1 — 추가 활동의 정체는 「업무 외 노동」이 아니라 「안심시키기」다
기획은 간식·빗질 같은 **추가 노동**을 상상했는데, 시터가 실제로 넣고 싶은 건
**노는 모습·자는 모습** — 인터뷰 #1 Q5의 보호자 최대 불안("말로만 잘 지낸다 하고 아니면 어쩌지")에 대한
시터 쪽의 자발적 응답이다. 인터뷰 #1 Q3의 "안심시키는 편"과 같은 동기가 **이번엔 좋은 방향으로** 나왔다.

### 발견 2 — "점수와 별개"라는 프레임이 노동을 무가치하게 만들었다
기획의 원래 논리("쉬운 활동으로 점수 부풀리기 방지")는 **수학적으로 성립하지 않는 걱정이었다** —
약속 이행의 분모는 보호자가 정하므로 추가 활동으로는 애초에 부풀릴 수 없다.
점수에 안 넣는 것 자체는 맞지만, **인정 장치가 아무것도 없는 "별개"는 그냥 무보상 노동**이었다.

## 반영 — 「먼저 챙긴 순간」 + 보호자 「고마워요」
- 이름: 추가 활동 → **먼저 챙긴 순간**
- 보호자가 각 순간에 **[💙 고마워요]** → 시터 화면에 표시되고 공개 프로필에 누적
- 공개: `먼저 챙긴 순간 32건 · 보호자 고마워요 28`
- 고마워요 받은 순간은 **시터도 지울 수 없다** (받은 인정은 기록으로 보존)
- 후기 칩에 「먼저 챙겨줘요」 추가

## 한계
- 고마워요를 안 눌러주면 여전히 무보상. 보호자 인터뷰 0명 문제가 여기도 걸림
- n=1

# 자료 #1 — 실제 보호자 인계문 (2026-08-11) ★ 첫 보호자 측 1차 자료

사용자가 당근 알바에서 **실제 보호자에게 받은 인계 메시지**를 공유했다.
지금까지 보호자 근거가 0명이었는데, **간접적으로나마 보호자가 실제로 무엇을 어떻게 전달하는지**를 처음 확인했다.

## 원문 요지 (두 마리: 감자, 만두)

**감자:** 마킹 → 기저귀 착용 / 식탐 → 식사 시 다른 아이와 분리 / 실외배변 습관 → 기저귀에 한 번에 많이

**만두:** 사람에게 입질 가능 / 기저귀 필수, **갈 때는 입질 방지를 위해 리드줄 채운 상태로** /
방석 위 터치 금지, 먼저 다가올 때만 쓰다듬기 / 밤에 사람 옆에서 자야 함 /
낯설면 밥 안 먹음 → 사료에 간식 섞기 / 떨어진 간식 만지면 입질 — 자리 비웠을 때 치우기 /
헛짖음 → "방석 들어가" 또는 몸으로 블로킹 / 슬개골 탈구 → 산책 불필요

## 이 자료가 확인해준 것

1. **버렸던 「시점 순 인계 카드」가 실제로 필요했다.** 이 인계문의 정보들은 전부
   **특정 행동의 순간에 소환돼야 하는 정보**다 — "리드줄 채우고 기저귀 갈기"는 배변 때,
   "간식 섞기"는 밥 때. 근본 원인 V2(정보를 수행 시점에 못 꺼냄)의 살아있는 표본
2. **보호자는 이미 이 문서를 쓰고 있다** — 카톡 장문으로. 구조가 없어서 매번 다시 쓰고, 시터는 스크롤로 찾는다
3. **안전 정보(입질 조건)가 케어 팁과 섞여 있다** — 구조화하면 안전 항목을 앞세울 수 있다
