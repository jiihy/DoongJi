## 1. 문제

> 보호자와 시터는 서로를 검증할 방법이 없어서 **매 건마다 관계를 0에서 다시 쌓는다.**

**1판에서 무엇이 틀렸나 (인터뷰로 확인)**

| | 1판이 믿은 것 | 실제 |
|---|---|---|
| 이력의 내용 | 확인된 돌봄 **건수** | **"내가 어떤 사람인가"** (Q6) |
| 왜곡되는 곳 | 수행 ("할 일을 했나") | **상태** ("아이가 어땠나") (Q2·Q3) |
| 왜곡의 이유 | 불이익이 걱정돼서 | **안심시키는 게 좋은 서비스라 여겨서** (Q3) |

세 번째가 가장 크다. **불이익을 없애는 정책만으로는 안 바뀐다.**

## 2. 이 제품이 하는 일

**시터가 "나는 이런 사람이다"를 보여줄 수 있게 하고, 그 주장 중 검증된 부분을 시스템이 따로 표시한다.**
돌봄 중에는 **판단이 아니라 관찰**만 남기게 해서, 완화될 여지를 형식으로 없앤다.

### 한 문장
> 잘 돌보는 사람이라는 걸 보여줄 수 있는 프로필. 그리고 "잘 지냈어요" 대신 "사료 절반 남김"이 남는 기록.

### 요구 수준의 상한선 (인터뷰 Q7)
> **"우리 강아지가 잘 살아서 안전하게 있구나를 보호자가 확인할 수 있는 정도만"**
> 이 선을 넘으면 숙제가 되고, 숙제가 되면 안 쓴다. 1판의 전체 체크리스트는 이 선을 넘었다.

## 3. 목표 & 성공 지표

### 1순위 — 완화가 실제로 줄었는가 ★
| 지표 | 목표 | 왜 |
|---|---|---|
| **비-최상 관찰값이 하나라도 포함된 돌봄 건의 비율** | **≥20%** | 모든 건이 전부 「다 먹음·정상·평소처럼」이면, 그건 기록이 아니라 의례다. 결정 3(판단→관찰)의 직접 검증 |
| 시터별 — 전 건을 최상값만 고른 시터 비율 | ≤30% | 위 지표를 시터 단위로 다시 봄 |

> **[추측] 20%·30%는 벤치마크 없는 초기 목표치다.** 실제 동물의 컨디션 분포를 모른다.

### 2순위 — 「사람됨」 가설이 맞는가
| 지표 | 목표 |
|---|---|
| 시터의 층 3(본인 소개) 채움률 | ≥70% |
| 보호자가 프로필에서 층 3까지 스크롤한 비율 | ≥50% |
| 층 2(가져온 후기) 등록 시터 비율 | ≥40% |

### 3순위 — 한 바퀴가 도는가
| 지표 | 목표 |
|---|---|
| 안전 신호 기록률 (돌봄당 1회 이상) | ≥90% |
| 24시간 내 보호자 확인율 | ≥70% (**여전히 최대 병목**) |
| 공개 프로필 링크 열람 | 시터당 월 ≥1건 |

## 5. 기능 목록

### P0 — 이것만으로 한 바퀴가 완결된다

| ID | 기능 | 화면 | 완료 조건 |
|---|---|---|---|
| **F1** | **시터 프로필 (3층)** ★ | S6 | **확인됨 / 가져옴 / 본인 소개**가 시각적으로 명확히 분리. 층 1은 시스템이 만들고 **시터가 편집 불가** |
| **F2** | **프로필 편집 (층 2·3)** ★ | S7 | 층 2: 타 플랫폼 후기 + **출처 링크 필수**. 층 3: 내 강아지 사진·메모 / 봉사·기부 이력 |
| **F3** | 인계 카드 작성 | O2 | 시점 5구간(입장·급여·산책배변·놀이투약·퇴장). 필수 5항목 미충족 시 확정 불가 |
| **F4** | 인계 카드 읽기 | S3 | **시점 순으로 정렬**되어 돌봄 중 해당 구간만 펼쳐 볼 수 있음 (V2 대응) |
| **F5** | **안전 신호** ★ | S4 | 사진(선택) + 「지금 무엇 중」(버튼) + **관찰값 3종**. **자유 서술 필드를 두지 않는다** |
| **F6** | 완료 → 보호자 확인 | S5·O4 | 요약 자동 생성. 보호자는 버튼 하나(**별점 없음**) + 선택적 한 줄. **자동 확인 없음** |
| **F7** | **공개 프로필** ★ | P1 | 로그인 없이 열람. **3층 구분 표시 + 각 층의 검증 수준 명시** |
| **F8** | **다음 카드 갱신 제안** ★ | O4 | 확인 직후, **비-최상 관찰값이 있었던 항목만** 다음 인계 카드에 추가 제안. 수락 시 `cards[].version +1` |
| **F9** | **긴급 신호** | S4 | 관찰값과 **독립된 버튼.** 누르면 기록 최상단 고정 + 보호자 즉시 표시 |

**F1·F2·F5·F7이 2판의 핵심이다.** 이 넷을 빼면 1판으로 돌아간다.

#### F8이 필요한 이유 (확인 병목)
보호자에게는 확인을 찍을 직접적 이득이 없다 — 애는 돌아왔고 결제도 끝났다.
버튼을 누르면 **시터의 프로필이 좋아질 뿐**이다. 그래서 안 누르고, 안 누르면 **층 1이 영원히 빈다.**

F8은 그 순간에 보호자 **자신의 이득**을 붙인다: *"이번에 산책 거부가 있었네요. 다음 인계 카드에 넣어둘까요?"*
→ 다음번에 **다른 시터**에게 맡길 때 이미 카드에 들어가 있다.

**부수 효과:** 제안은 비-최상 관찰값이 있을 때만 뜬다.
→ **시터가 정직할수록 보호자에게 이득이 생긴다.** 두 인센티브가 같은 방향으로 정렬된다.

#### F9가 필요한 이유 (User Flow 구멍 1)
관찰값 3종(사료·배변·활동)에는 **"아파 보인다 / 다쳤다 / 안 보인다"를 넣을 자리가 없다.**
1판의 「이상 있음」을 관찰값으로 교체하면서 긴급 경로가 통째로 사라졌고,
그 상태로는 **창고에 갇힌 고양이 유형의 사건을 다시 못 잡는다.**
긴급은 **판단이 아니라 행동을 요구**하는 것이므로 완화 문제와 무관하다.

#### F5 관찰값 명세 (완화 여지를 없애는 지점)
| 항목 | 선택지 | 보호자가 대조 가능한가 |
|---|---|---|
| 사료 | 다 먹음 / 절반 / 거의 안 먹음 | **가능** (귀가 후 그릇) |
| 배변 | 정상 / 묽음 / 없음 | **가능** (패드) |
| 활동 | 평소처럼 / 조용함 / 숨어 있음 | 부분 |

**"오늘 어땠나요?" 같은 판단형 질문과 자유 서술 칸을 두지 않는다.** 완화는 문장을 쓸 때 일어난다.

## 6. 데이터 모델 (localStorage · 키 `petcare.v2`)

```js
{
  sitter: {
    id, name, since,
    external:      [{ id, platform, url, quote, addedAt }],        // 층 2
    myPet:         [{ id, photo, memo, at }],                      // 층 3
    contributions: [{ id, kind, org, period, memo }]               // 층 3 (봉사·기부)
  },
  owner: { id, name },
  pets:  [{ id, name, species, age }],
  cards: [{ id, petId, version, updatedAt,
            items: [{ id, phase, title, detail, required }] }],    // phase = 시점 5구간
  jobs:  [{
    id, petId, cardId, cardVersion,
    status,                        // promised|in_progress|awaiting|confirmed|disputed|unconfirmed
    cardViewedAt, startedAt, completedAt,
    signals: [{ id, at, photo, moment,                             // 안전 신호
                obs: { food, poop, activity },                     // 관찰값. 자유 서술 없음
                urgent: false,                                     // F9 긴급 (독립 플래그)
                afterCompletion: false }],                         // F12 사후 기록 여부
    confirmation: { at, comment } | null,
    dispute:      { at, reason }  | null
  }]
}
```

**모델의 규칙 4개**
1. `cards`는 `pets`에 붙는다 → 정보가 '건'이 아니라 **동물**에 축적
2. `status === 'confirmed'` 인 job만 **층 1**에 집계 → 층 1은 보호자가 찍어준 것만
3. **층 1은 `sitter` 객체에 저장하지 않는다.** `jobs`에서 파생 계산 → 시터가 편집할 수 없음
4. `signals[].obs`는 **열거값만** 받는다. 자유 텍스트 필드가 스키마에 없다

## 10. 이 PRD가 틀렸다면 무엇이 관찰되는가

- 관찰값이 100% 최상값 → 결정 3 기각. 원인이 형식보다 깊은 곳에 있음
- 층 3 채움률 0% → 시터가 원한다고 말한 것과 실제 행동이 다름. Q6 재해석 필요
- 보호자가 프로필을 안 보고 가격·거리로만 고름 → **제품 전제 전체가 무너짐**
- 보호자가 관찰값을 귀가 후 대조하지 않음 → "검증 가능한 사실"이 실제로는 검증에 안 쓰임
