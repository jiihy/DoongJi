## 0. IA를 가르는 결정 5개

| # | 결정 | 일반적인 방식 | 여기서 | 근거 |
|---|---|---|---|---|
| 1 | **「내 프로필」이 루트 레벨** | 프로필은 `설정 > 프로필`에 묻힘 | 탭 1급 시민 | 이력이 사람에게 귀속되는 게 제품의 요점 |
| 2 | **반려동물이 독립 객체** | 보호자 계정의 하위 데이터 | 양쪽에서 참조하는 별도 객체 | 정보가 대화방이 아니라 동물에 붙어야 축적됨. **인터뷰 Q1로 확인** |
| 3 | ~~「못했음」이 정상 상태값~~ → **「관찰」을 묻는다** | "오늘 어땠나요?" (판단을 요구) | **"밥 얼마나 먹었나요?"** (관찰을 요구) | 판단을 물으면 완화된다. 관찰은 완화가 안 되고 **보호자가 대조 가능** |
| 4 | **프로필이 3층으로 분리** ★신규 | 후기·소개가 한 화면에 섞임 | **확인됨 / 가져옴 / 본인 소개**를 눈에 보이게 구분 | 자기신고와 검증된 것을 섞으면 신뢰 장치가 아니라 자기주장이 됨 |
| 5 | **보호자에게도 이력이 쌓인다** ★신규 | 보호자는 평가하는 쪽 | 양쪽 모두 프로필을 가짐 | 1판은 시터 보호 조항 6 : 보호자 1로 기울었음. 보호자가 '을'이 되는 구조 |

### 결정 3의 교체가 핵심이다
1판의 「했음/못했음/이상」 전체 체크는 **숙제였다.**
인터뷰 Q7의 기준 — *"우리 강아지가 잘 살아서 안전하게 있구나를 확인할 수 있는 정도만"* — 을 넘었다.
요구의 **양**을 줄이는 게 아니라 **종류**를 바꾼다: 판단 → 관찰.

## 0-1. 신뢰의 3층 (결정 4 상세)

| 층 | 내용 | 검증 | 표시 |
|---|---|---|---|
| **확인됨** | 이 서비스에서 보호자가 확인 찍은 돌봄 | 검증됨 | 최상단. 도장 표식 |
| **가져옴** | 타 플랫폼 후기 | 출처 링크까지만 | 중간. 출처 명시 필수 |
| **본인 소개** | 내 강아지와의 일상, 유기견 봉사·기부 | **검증 안 됨** | 하단. "본인이 작성" 명시 |

**세 층은 시각적으로 절대 섞지 않는다.** 섞으면 자기주장을 검증된 것처럼 포장해주는 꼴이 된다.

## 1. 정보 구조 (객체 모델)

```
Pet (반려동물)  ← 정보 귀속의 중심. 보호자에 종속되지 않음
 └─ HandoffCard (인계 카드)   1:1, 버전 있음
     └─ CareItem (약속 항목)   n개. 수행 시점 순서로 정렬   ← V2 대응
         · 시점: 입장 / 급여 / 산책·배변 / 놀이·투약 / 퇴장

CareJob (돌봄 건)
 ├─ pet / sitter / owner
 ├─ SafetySignal (안전 신호)   n개. 돌봄 중 가볍게 남김   ★ 결정 3
 │   · photo (선택)
 │   · moment: 지금 무엇 중인가 (버튼 1회)
 │   · observation: 관찰값 — 판단이 아님
 │       예) 사료: 다 먹음 / 절반 / 거의 안 먹음
 │           배변: 정상 / 묽음 / 없음
 │           활동: 평소처럼 / 조용함 / 숨어 있음
 └─ Confirmation (보호자 확인)   ← 이게 찍혀야 「확인됨」층에 들어간다
     · confirmedAt, ownerComment  |  Dispute { at, reason }

SitterProfile (시터 프로필)   ★ 결정 1·4 — 건수 카운터가 아니라 사람을 보여주는 페이지
 ├─ [층 1] 확인됨    ← Confirmation 있는 CareJob만. 시스템이 만듦. 시터가 못 건드림
 ├─ [층 2] 가져옴    ← ExternalReview { platform, url, quote, addedAt }
 └─ [층 3] 본인 소개 ← MyPetLog (내 강아지와의 일상) / Contribution (봉사·기부)

OwnerProfile (보호자 프로필)   ★ 결정 5 — 대칭
 ├─ 확인을 찍은 비율
 ├─ 인계 카드를 채운 정도
 └─ 함께한 시터 수
```

**핵심 규칙 3개**

1. `Confirmation`이 없는 `CareJob`은 **층 1(확인됨)**에 들어가지 않는다 → 이력은 보호자가 찍어준 것만
2. **층 1은 시터가 편집할 수 없다.** 층 2·3만 시터가 만든다 → 검증된 것과 자기주장의 분리
3. `observation`은 **판단이 아니라 관찰값**만 받는다. "잘 지냈어요" 같은 자유 서술 필드를 두지 않는다
   → 완화는 문장을 쓸 때 일어난다. 문장을 쓰게 하지 않는다

## 2. 화면 계층

### 시터 (Sitter) — 10개

```
S. 시터
├─ S1  오늘                              [홈 탭]
├─ S2  돌봄 목록                         [돌봄 탭]
│   ├─ S3  인계 카드 읽기                 ← 시점 순
│   ├─ S4  안전 신호 남기기 (돌봄 중)     ★ 결정 3. 사진 + 순간 + 관찰값
│   └─ S5  완료 / 확인 요청
├─ S6  내 프로필                          [프로필 탭] ★ 결정 1·4
│   └─ S7  프로필 편집                    ← 층 2(가져온 후기) · 층 3(내 강아지·봉사)
├─ S8  담당했던 아이 목록                 [아이 탭]
│   └─ S9  아이 상세 — 카드 히스토리
└─ S10 설정
```

### 보호자 (Owner) — 5개 ★ 1급 사용자로 승격

```
O. 보호자
├─ O1  시터 찾기 / 프로필 열람            ← 3층을 보고 고른다
├─ O2  인계 카드 작성 / 수정
├─ O3  돌봄 중 보기                       ← 안전 신호 수신
├─ O4  완료 확인
└─ O5  내 프로필 (보호자 이력)            ★ 결정 5. 대칭
```

### 공개 (Public) — 1개

```
P1  시터 공개 프로필
    · 링크로 열림, 로그인 불필요. 3층 구분 표시
    · 플랫폼 밖으로 들고 나가는 통로
```

### 총 화면 수: **16개** (시터 10 / 보호자 5 / 공개 1)
1판 18개에서 감소. 상세 체크 화면(수행 체크·이상 보고 작성)이 안전 신호 1화면으로 통합됨.

## 4. P0 / P1 구분

**P0의 정의:** 「프로필 → 선택 → 약속 → 안전 신호 → 확인 → 프로필에 축적」 한 바퀴가 도는 최소 집합

| 화면 | 이름 | 우선순위 | 이유 |
|---|---|---|---|
| S6 | 내 프로필 (3층) | **P0** ★ | 새 전제의 본체. 「사람됨」을 보여주는 곳 |
| S7 | 프로필 편집 (층 2·3) | **P0** ★ | 가져온 후기 · 내 강아지 · 봉사 이력. 시터가 원한다고 말한 것 |
| O2 | 인계 카드 작성 | **P0** | 약속이 생기는 지점 |
| S3 | 인계 카드 읽기 | **P0** | V2 대응 — 시점 순으로 꺼내 보는 곳 |
| S4 | 안전 신호 | **P0** ★ | 결정 3. **판단이 아니라 관찰**을 남기는 곳 |
| S5 + O4 | 완료 → 보호자 확인 | **P0** | 층 1(확인됨)이 성립하는 지점 |
| P1 | 공개 프로필 | **P0** ★ | 3층 구분 표시. 빼면 새 전제가 검증 안 됨 |
| O1 | 시터 찾기 | P1 | 프로토타입은 시터 1명 고정 |
| O3 | 돌봄 중 보기 | P1 | S4 신호를 같은 화면에서 확인 가능 |
| O5 | 보호자 프로필 | P1 | **결정 5의 구현체지만 오늘은 범위 초과** |
| S1, S2 | 오늘 · 돌봄 목록 | P1 | 건이 1~2개 |
| S8, S9 | 아이 목록·상세 | P1 | 재의뢰는 2회차부터 |
| S10 | 설정 | P1 | — |

### P0 화면 수: **7개** (S5·O4를 한 흐름으로 셈)

`S6·S7 프로필 만들기 → O2 카드 작성 → S3 읽기 → S4 안전 신호(관찰) → S5·O4 완료·확인 → S6 층1 누적 → P1 공개`

**1판 P0와의 차이:** 수행 체크(3상태값 전체)와 이력 공유가 빠지고, **프로필 3층**이 들어왔다.
결정 5(보호자 프로필)는 P1로 미뤘다 — **정의에는 넣었는데 프로토타입에는 없다.** 알고 미룬다.

## 5. 이 IA가 틀렸다면 무엇이 관찰되는가

- 시터가 **층 3(본인 소개)을 안 채운다** → 인터뷰 Q6에서 원한다고 말한 것과 실제 행동이 다름. 결정 4 재검토
- 보호자가 **층 1과 층 3을 똑같이 신뢰한다** → 3층 구분이 무의미. 오히려 자기주장을 검증된 것처럼 포장해주는 꼴이 됨
- 시터가 **「프로필」 탭에 거의 안 들어간다** → 결정 1이 틀림. 프로필은 본인이 아니라 남이 보는 것 → 탭 대신 공개 페이지만
- 보호자가 **O4 확인을 안 찍는다** → 층 1이 안 쌓임. 확인 병목(`05-user-flow.md`)이 여전히 최대 위험
- 관찰형 질문에도 시터가 **뭉개서 답한다** → 결정 3(판단→관찰) 기각. 형식으로 완화를 못 막음
- 보호자가 시터를 **가격·거리로만 고른다** → 프로필 자체가 구매 결정에 안 쓰임. 제품 전제가 무너짐
