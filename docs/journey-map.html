User Journey & Critical User Journey

신뢰의 단위를 '건'에서 '사람'으로

보호자와 시터는 서로를 검증할 방법이 없어서 매 건마다 관계를 0에서 다시 쌓는다. 약속·수행·확인의 이력이 사람에게 남지 않기 때문이다. 인계 정보를 매번 새로 만드는 것은 원인이 아니라 증상이다.

03 — Findings

여정에서 나온 것

발견 1

두 사람의 감정 최저점이 같은 단계에 있다

보호자 −1.5(6단계 "또 처음부터"), 시터 −2(6단계 "증명 못 함"). 둘 다 "다음 건"에서 바닥을 친다. 돌봄 자체가 아니라 건과 건 사이가 문제라는 뜻이고, 이는 문제 정의(신뢰의 단위가 '건')를 여정 쪽에서 지지한다.

발견 2

시터의 통증이 더 깊은데, 완충 장치가 없다

보호자는 최소한 감시(라이브·사진)라도 갖고 있다. 불완전하지만 무언가는 한다. 시터에게는 대응 수단이 아예 없다 — 이력을 들고 나갈 방법 자체가 없기 때문이다. 주 사용자를 시터로 잡은 결정을 지지한다.

발견 3

CUJ의 병목이 주 사용자가 아닌 쪽에 있다

이력이 성립하려면 보호자의 확인(O4)이 반드시 찍혀야 한다. 그런데 보호자는 이 제품의 주 사용자가 아니다. 열쇠를 부 사용자가 쥐고 있다. 서비스 정책 단계에서 반드시 다뤄야 할 구조적 위험.

04 — Critical User Journey

끊기면 안 되는 한 바퀴

확인 CONFIRMED

보호자가 인계 카드를 만들고 → 시터가 수행을 기록하고 → 보호자가 확인을 찍어 → 그 이력이 시터에게 귀속되어 → 다음 고객에게 보여지기까지. 이 한 바퀴가 끊기면 제품은 그냥 체크리스트 앱이 된다.

  1. 1

    인계 카드 작성

    O2

    첫 작성 10분 이내 · 필수 5항목 채움률 100% · 2회차 작성 2분 이내

    끊기면 — 약속이 없으면 나머지 전부 무의미. 카톡으로 회귀

  2. 2

    카드 열람

    S3

    방문 전 열람률 100% · 방문 중 재열람 1회 이상

    끊기면 — 약속이 성립하지 않음. 수행 기록이 형식만 남음

  3. 3

    수행 체크

    S4진짜 시험대

    항목 체크 완료율 ≥90% · 「못했음·이상」 사용 건이 전체의 ≥10%

    끊기면 — 「했음」만 100%면 겉으론 잘 도는 앱이지만 신뢰 장치로는 완전 실패. 이 지표를 대시보드 1순위로 둔다

  4. 4

    완료 · 확인 요청

    S6

    돌봄 종료 후 10분 내 발송률 ≥90%

    끊기면 — 지연될수록 보호자 기억이 흐려져 확인 품질이 떨어짐

  5. 5

    보호자 확인

    O4최대 병목

    24시간 내 확인율 ≥70%

    끊기면 — 확인이 없으면 이력이 성립하지 않는다. 그런데 보호자에게는 찍을 직접적 이득이 없다. 정책에서 못 풀면 여기서 끊긴다

  6. 6

    이력 귀속

    S7

    확인 건 누적 반영 100% · 시터의 7일 내 이력 열람 ≥1회

    끊기면 — 시터가 안 보면 IA 결정 1(이력을 탭 1급으로 둔 것)이 기각됨

  7. 7

    이력 공유

    P1

    시터 링크 공유 월 ≥1회 · 링크 열람 ≥1건

    끊기면 — 아무도 공유하지 않으면 "이력을 들고 다닌다"는 가정 자체가 기각

05 — Unverified

미검증 표시

아래는 근거가 아니라 가정이다. 이 위에 무엇을 쌓았는지 알고 쌓는다.

시터 감정값 −2 (증명 못 함) — 해외 자료(프로필 삭제 후 리뷰 세탁)와 추론에 기반. 한국 시터 인터뷰 없음추측
보호자 6단계 "또 처음부터" — 시터 고정 실패가 실제로 얼마나 흔한지 확인 못 함추측
CUJ 성공 기준의 수치 (70% · 90% · 10%) — 벤치마크 없음. 초기 목표치일 뿐 검증된 기준선이 아님추측
「못했음」 사용률 ≥10% — 실제 돌봄에서 미수행이 얼마나 발생하는지 데이터 없음추측
시터 → 보호자 방향의 불신 — 해외 자료(시터 안전 문제)만 있고 한국 사례는 찾지 못함추측
